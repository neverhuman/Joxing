## Objective and evidence

Qualify the released full-body DynSyn-SAC controller as a possible source of useful muscle behavior, then determine whether it can support a new unassisted stance/reach teacher. This is a motor prerequisite for opponent-aware self-play. Non-goals: claiming a walking policy boxes, replacing the anatomy, bypassing sporting gates, copying future opponent state into an actor, or changing the completed v0.0.5 protocol.

The [upstream release](https://github.com/LNSGroup/msgym/releases/tag/Checkpoints) supplies `LocomotionFull.zip`. Its published and independently checked SHA256 is `2b2f0f1007d530db76463e7d3d5fb309b52c7b2a53649920ddfd9cf8a6880c57`; size 223,978,082 bytes. The ignored local archive is `runs/upstream-checkpoint-inspection/LocomotionFull.zip`. [Acquisition receipt](../artifacts/v0.0.5/upstream-checkpoint-inspection.json) and [reproducible metadata receipt](../artifacts/v0.0.5/upstream-checkpoint-metadata.json) are curated; the large weights stay outside Git.

Plain saved metadata reports 45 million upstream training transitions, 64 environments, three 1,024-unit hidden layers, a 3,601-value observation, 700 normalized actuator outputs and 138 underlying synergy groups. Those are upstream saved counters, not our training or verified competence. The checkpoint includes a separate observation normalizer; `best_env.zip` is a pickle despite its suffix. The inspection only reads ZIP/JSON metadata and does not deserialize models, tensors or that normalizer. Its recorded CUDA availability does not qualify GPU physics.

Pinned msgym's `locomotionFull_v1.py:_get_obs` includes joint pose/velocity/acceleration, activation, muscle force/length/velocity, keypoint position and current/future **self-reference trajectory** targets. Joxing stance supplies 1,023 values and 138 fixed group commands. These interfaces are incompatible. The Joxing stance learner borrows the upstream group partition and sigmoid transform. The separate v6 native adapter now executes the released learned state-dependent `DynSynLayer`; these remain distinct observation/action contracts. The [DynSyn paper](https://arxiv.org/abs/2407.11472) motivates this additional adaptation, whose value must still be measured here.

The following source-level issue was reproduced in v6: the saved top-level `dynsyn_weight_amp` is `None`; `SAC_DynSyn._setup_model()` passes that into the actor layer, whose `forward()` then uses unit intra-group weights. The training schedule at saved step 45,000,000 instead gives `min(0.1, 5e-9*(45e6-30e6)) = 0.075`. The amplitude is a Python attribute, outside the layer tensor state dictionary. The pinned evaluation script loads without explicitly restoring that scheduled value. This was confirmed as a load-time behavior mismatch; v6 retains both default-load and explicitly restored diagnostics plus exact corrected save/load tests. Do not silently patch the read-only submodule or assume that loading the model preserves its training-time decoder behavior.

## Ordered work and acceptance

1. **Archive and dependency contract.** Keep the release URL/hash, saved config and upstream code/model pins in a new manifest. Validate the full actuator-name map and all 700 muscles exactly once; inspect the sample trajectory's provenance and compatibility before using it. Reproduce the metadata command below. Determine the checkpoint's required source revision and compatible dependency versions; use an isolated environment when necessary. Stop on unknown layout/model/version or missing normalizer rather than guessing a feature order.
2. **Decoder/load oracle.** Build an adapter returning the full normalized 700-muscle vector. With a frozen synthetic observation, compare the checkpoint's default load, the expected scheduled amplitude, deterministic prediction and save/load roundtrip. Assert shape/range/finite output, explicitly record both amplitude values and restore the selected contract on every load. Add tests that fail if amplitude or normalizer restoration is omitted. Freeze normalizer statistics for evaluation (`training=False`, reward normalization off); prove observations do not update them.
3. **Native teacher replication.** Before training or adding gloves, run the exact upstream task with `kinematic_play=False`, ordinary gravity and its actual termination/trajectory rules. Register 20 attempted episodes, seed/phase selection and a 15-minute/1-million-physics-step cap before execution; keep every attempted result and fault. Log native and Joxing-style support/fall telemetry separately. Save initial state, commands, full snapshots, normalizer/decoder state, fixed first-scenario video and source hashes. A native locomotion completion is a teacher diagnostic, not the five-second stance or boxing gate. Do not report pose playback as muscle-driven control.
4. **Transfer compatibility.** In a separately hashed variant, add Joxing's glove inertia and map observations from actual native state in the exact saved order/units. Validate mapped features against the original environment at identical states before any rollout. Check root frames, equality projection, muscles, muscle force/length/velocity, trajectory phase and future self-target construction. Compare default and glove variants on paired states; quantify the shift. A walking imitation reference supplies task goals, not historical opponent state. New recurrent/game observations remain separate work.
5. **New motor protocol.** Establish feasible stationary and initial-fall-recovery reset banks with absolute pose/velocity, COM, support and muscle authority diagnostics. Keep the old moving starts/evidence. Compare a bounded teacher-assisted/distilled initialization against a matched random initialization, then evaluate both unassisted using identical native physics. A static reference substituted into a walking policy is out of distribution and must be labeled. Use a state-conditioned decoder capable of representing the teacher's intra-group variation; the current fixed 138-group map may not reproduce all 700 outputs. Version observation/action/normalizer/decoder hashes; incompatible actors must be rejected. Select gamma by an explicit physical timescale in the new protocol. Freeze seeds, reset splits, wall/step budgets and checkpoint selection before outcomes.
6. **Motor proof then game.** Require the unchanged five-second development gate before the formal stance/recovery proof in `docs/TRAINING.md`. Only after motor/contact/referee gates pass should `observations.py`, temporal history, causal queues, simultaneous stepping and the historical league be integrated under P2/P5. Memoryless/stacked/recurrent and zero-delay/jitter comparisons need equal compute and frozen panels. A successful teacher is a useful dependency, not automatic tactical competence.

Hard parts: checkpoint source/normalizer compatibility, the scheduled decoder attribute, native root frames, future self-reference timing, altered glove inertia, distinguishing playback from physical control, and a decoder whose representable commands differ from fixed grouping. Preserve the teacher's control cadence and action transform initially. Do not add rate filters only at evaluation or combine anatomy/reward/history changes into one causal claim.
