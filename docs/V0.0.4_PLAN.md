The user requested a major implemented iteration. v0.0.3 was a planning milestone, with no released code or training. v0.0.4 carries its prerequisite work into executable code, then runs a bounded SAC development pilot. Its scientific outcome is measured, not promised. [Historical detailed plan](V0.0.3_PLAN.md), [game contract](GAME.md), [status](STATUS.md).

## Objective, scope and stop conditions

Deliver native-root gravity simulation, full-muscle feedback observations/actions, physical support and reset audits, complete evaluation snapshots, bounded SAC training, paired development evaluation and visible evidence. Preserve the 700 native muscles, 42 equalities, segment inertia and candidate boxing points. Do not claim a passed motor proof from a development pilot. Stop on invalid resets, unknown floor-contact roles, unexpected external support/gravity compensation, numerical failure, replay mismatch, incompatible hashes or budget limits. Keep failure evidence. A valid physical fall is an outcome, not a numeric fault.

## Execution sequence

1. Audit the real source keyframe and native root. It starts with ~0.010506 equality residual; do reset-only Newton projection with the root unchanged, prepare 200 ms at excitation .02 under gravity, project residual/velocity once more, then begin evaluation without state writes. Accept bilateral foot load through the final 100 ms, equality error <1e-8 and penetration <=2 mm. Log source/loaded/projected residuals and every preparation correction. This measures local balance, not standing up.
2. Preserve and test all source muscle parameters, segment masses/inertias and exact .566 kg glove increment. Use named 138-group partition with upstream sigmoid; validate all 700 names exactly once. Derive floor support from staged signed contact force; require persistent non-foot support/tilt/drop before motor failure.
3. Expose a Gymnasium feedback task with 1 ms CPU physics and 10 ms control. Real observation blocks: relative qpos, bounded velocities, 700 activations, pelvis upright direction, pelvis/hand errors, support and previous action. Hash observation/action/model contracts. Injected test push is scheduled by physics tick; no hidden assistance.
4. Add meaningful contact-sign, momentum, persistence, reset, action, observation, failure, truncation, fault and snapshot tests. Prove push impulse and restore with a scheduler fixture; fixture time repositioning is explicitly not policy survival evidence. Keep every v0.0.2 regression passing. Run a two-worker/64-transition smoke test to verify process orchestration without claiming optimization.
5. Run a 32-reset bank and 12 root-stress cases (four directions at 2/1/0.5 ms). Finite short falls do not rule out all root singularities. Preserve source commit/hash and all results.
6. Commit source before the actual remote pilot. Recheck xbabe1 load/RAM/disk. Run seed 73, four CPU workers, one BLAS/OpenMP/PyTorch thread, at most 100,000 admitted control transitions/one million training physics substeps/30 minutes. SAC uses [256,256], batch 256, 10,000 warmup transitions, one optimizer update per transition, auto entropy and 100,000 replay capacity. Linux uses CPU PyTorch wheels; no CUDA driver changes. Save progress and atomic checkpoints every ~15 seconds.
7. Freeze protocol before learning and compare frozen initial/final deterministic policies on development IDs 30000–30031 with identical full starting states. Report all 64 attempts, paired survival seconds and bootstrap reset CI (seed 61004), five-second survivors, twenty-second successes and faults. Training resets are 100000–100063. This pilot's primary metric is survival seconds; the later formal motor proof retains recovery-success improvement as its primary metric.
8. Independently verify checkpoint hashes, raw rows, paired initial-state hashes, reset accounting, replay and final summaries. Render preselected scenario 30000 and plot actual episode durations and paired evaluation outcomes. Do not select a flattering video. Publish limitations, failed gates and exact next work. Push source/evidence/docs and tag v0.0.4 only with implemented scope.

Pilot continuation requires at least 16/32 development starts surviving five seconds, zero invalids and passing model/replay tests. Failure blocks the planned 500,000-transition-per-seed formal run and its 768 held-out stance/recovery attempts; it does not become a successful motor gate. No use of final IDs 40000/50000 in this development release. If the pilot passes, formal proof is a separate frozen run under the existing four-hour/40-million-total-physics-substep/10-GiB cap.
