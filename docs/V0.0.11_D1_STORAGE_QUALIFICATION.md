The new `joxing-lossless-sensor-evidence-v1` format uses gzip JSON and NumPy-readable
ZIP_LZMA arrays. A directory manifest binds stored bytes and decoded JSON or
array dtype/shape/byte digests. Externally pinned manifest hashes anchor those
claims; changing all self-described hashes cannot authenticate invented data.
Readers accept old evidence directly and decode new evidence in memory, with
no expanded files written elsewhere. All old evidence stays intact.

`src/joxing/sensor_packed_evidence.py` subclasses the original collector and
inherits its exact choose/capture methods. Only saving changes. The physical,
observation, sensor delivery, history, action transport and controller modules
are byte-identical to ef42c872d13bfebb16b347f842ba11f0b8b8e776. Three auditors
use bounded readers; their physical/rule/transport/replay criteria are unchanged.
The implementation receipt lists all unchanged module hashes.

Limits cover compressed/decompressed bytes, member count, primitive dtype,
header dimensions, JSON nesting, duplicate/path-traversal members, object arrays,
CRC, dictionary allocation and decoded semantics. ZIP LZMA uses an explicitly
bounded decoder because the standard ZIP adapter has no output-length argument.
Streamed writes check raw credits before growth, including seek/backpatch and
atomic replacement peaks. Failed temporary files remain charged and retained;
a fresh attempt cannot overwrite them. Fault reserves remain available.

The27new tests cover corrupted values/dtype/shape after container rehashing,

integers, tick-string keys, malformed/oversized archives and JSON, quota failures,
