## Hard cases and tests

Pure tests precede physical runs: zero/one/two/20/40tick delays; ties and deliberate
reordering; delayed older packet after a newer sample; dropped first sample;
empty history and explicit command hold; duplicate identical vs conflicting ID;
capacity/future/wrong owner/reset rejection; immutability; snapshot with pending
old/new packets; controller/sensor RNG isolation. A received sample can never
have sampled_tick>decision_tick or received_tick>decision_tick. The newest
available sample wins; late older arrivals may enter past history but cannot
replace the latest actor input. Never sort by network arrival as physical time.

Use deterministic schedules to distinguish visible effects. A20tick sensor lag
at50Hz should expose the previous decision state, not merely a different receipt
label for current features. A40tick lag followed by0tick lag should exercise
reordering and stale-latest protection. Verify on asymmetric moving limbs with
real nonzero native velocities; mirrored scalar math alone is insufficient.

Paired action perturbation: alter A's current choice while comparing B's already
assembled ActorInput, own RNG and chosen command. Change pending A packets and
hidden activations without changing the physical sampled evidence; B's input
must remain identical. Ensure failed pair validation changes neither queue.

sweep: first exact zero-delay D0 oracle from retained seed/start/controller, then
