## Objective and proof question

Build a falsifiable test suite for one full-muscle athlete under ordinary gravity, then measure whether a feedback motor learner improves stance and recovery within a fixed compute budget. The critical question is: **can the actual embodiment support itself and recover from a small, measured disturbance without a fixed pelvis, gravity compensation or pose writes?**

v0.0.2 established assisted muscle-to-contact scoring and withdrawal: 192/192 trained withdrawals versus 0/192 baseline, with both hitting 192/192. Its fixed-pelvis, zero-gravity arm controller cannot answer the new question. Preserve that result and its fixtures as a regression baseline.

Two outcomes must be reported separately:

- **Test-platform completion:** model/reset/support/assistance checks, failure accounting, replay and bounded benchmark produce auditable results. A failed stance experiment is a valid measured outcome.
- **Motor gate passed:** all three frozen policies meet the absolute stance/recovery criteria below. Claim learned improvement only if the paired evaluation also supports it. Neither outcome enables competitive self-play; production geometry and referee gates remain open.

Non-goals: a playable match, two-agent PPO, footwork, learning a punch under gravity, final foul/fall adjudication, full anatomical scoring surfaces, empirical force calibration, injury mechanics, muscle pruning, codec distillation, GPU simulator parity repair or host driver changes. Do not expand this iteration to all of P1–P5.

Assumptions/dependencies: pinned MuJoCo 3.8.0 and both submodules; all 700 native muscles; CPU reference physics; procedural stance goals without a motion-capture download; explicit additional learner dependencies locked before training. Existing compute inventory is historical availability, not a reservation. If a dynamically feasible reset cannot be established, publish the blocker rather than train against a fabricated reset.

## Ordered implementation

### 1. Register the test protocol and honest outcomes

Create frozen dataclasses `BalanceConfig` in `balance.py`, `SupportConfig` in `support.py`, `StanceConfig` in `stance_env.py` and `EvalProtocol` in `stance_eval.py`. Resolve JSON to these types with finite/range/integer-tick validation; unknown fields fail. Define outcomes `success`, `physical_failure`, `invalid`, `not_run`. A true fall is physical failure; engine warning/nonfinite/reset/contact overflow is invalid; a blocked prerequisite is not_run. Store planned, attempted, valid, invalid and not_run counts separately. Never substitute a new scenario for a failed one.

`BalanceConfig`: variant ID, root representation, gravity, physics/motor periods, solver settings, collision exclusions, equipment. Default physics is 1 ms implicitfast, gravity `[0,0,-9.81]`, muscle update every 10 ms. Derive dimensions from compilation. `EvalProtocol`: scenario specifications, seed namespaces, budgets, thresholds, initial-policy hashes, final-checkpoint selection rule, snapshot schedule and fixed video IDs. Final checkpoint hashes belong in result receipts; they cannot be known before training. Include config/schema/source/model/action/observation/reset hashes in every result. Reject mismatched versions on restore/evaluation.

Each evaluation row has `attempt_id=(seed,policy,scenario_id)`, `status`, `reason`, `initial_state_hash`, `policy_hash`, `protocol_hash`, `elapsed_sim_s`, `physics_steps`, `stable_s`, `max_tilt_rad`, `delivered_push_Ns`, `assistance`, `snapshot_paths`. Include `scheduled` versus `attempted` flags; only finite JSON values are allowed, so unavailable measurements are null. Enforce unique attempt IDs and exact planned-row coverage in the independent verifier. For every summary: `planned = attempted + not_run`, `attempted = valid + invalid`, and `valid = successes + physical_failures`.

### 2. Establish a mechanically honest gravity model

Implement `build_balance_model(config) -> BalanceModel` in `balance.py`: one intact native-root human, physical floor and two explicitly inertial 0.283 kg gloves. Preserve native muscle parameters, tendon routing, 42 equalities, segment mass/COM/inertia and enabled colliders. Add a complete semantic registry for every enabled collider in this rig, including floor and native leftovers. Do not infer foot contact from body height. Log existing exclusions and unresolved self-contact limitations; no claim of complete boxing collision coverage follows.

The native pelvis uses six scalar coordinates beneath a rotated frame. Tests must map root displacement and anatomical orientation through engine transforms, rather than assuming that a `pelvis_tz` change is world vertical. Check native 85/85 qpos/qvel, 700 controls/activations and equipment mass increment 0.566 kg. Compare named non-root body/tendon/muscle properties to the pinned source exactly where applicable (float geometry/inertia comparison tolerance 1e-12).

Implement `run_root_probe()` with passive forward/back/left/right falls, yaw rotations and near-sideways configurations. Record world poses/velocities, warnings, contact impulses, root Jacobian singular values and last valid states. Test 2/1/0.5 ms at unchanged 100 Hz control. A passive fall is expected, and is not a numeric defect. Differentiate coordinate singularity from true physical instability using the root Jacobian and finite continuation; save the counterexample before proposing surgery.

Only if native-root diagnostics expose a blocker, implement separately hashed `free-root-diagnostic-v1`. Remove/remap invalid keyframes; derive qpos using compiled world pose, quaternion conventions and model-aware velocity mapping. Validate non-root world transforms (<1e-9 m/rad at mapped poses), velocities (<1e-8 m/s/rad/s away from singularities), masses/inertias and muscle/tendon behavior. Verify six root DOFs, not an assumed qpos count. Quaternions q and -q are equivalent. Root-specific damping/armature differences must be explicit. Do not select a variant using final evaluations or reuse incompatible checkpoints. If neither variant is mechanically usable, stop here with a root blocker receipt.

### 3. Test support and build reset states before learning

`support.py`: implement `SupportMonitor.update(contacts, kinematics, dt)` and serializable state. Stage contact forces with existing `step_contacts`; sum the signed upward force **on the athlete**, including reversed geom order and multiple manifold points, once per substep. Classify `calcn_r/l` and `toes_r/l` as foot support; hands, knees, trunk and head are non-foot support. All other physical colliders require explicit categories. Publish per-foot force, non-foot force, persistence, torso tilt, root drift and failure reason. COM projection is a diagnostic, not a dynamic fall oracle.

Candidate motor-test failure contract (not sporting adjudication): non-foot upward load >=10% body weight continuously for 50 ms; or torso tilt >=60 degrees for 100 ms; or pelvis drop >=0.30 m from the accepted reset for 100 ms. Independently log flight/foot load and raw signals. A single glove brush and a briefly lifted foot must not produce an automatic fall. Persistence uses elapsed time, not sample count. Calibrate numerical noise on development fixtures and freeze constants before final proof; any change creates a new protocol. Injury/foul/exit meanings remain outside this motor test.

`resets.py`: implement `make_reset_bank()`, `validate_reset()` and `reset_from_spec()`. Start with the native keyframe, solve only named procedural stance/guard targets respecting native equalities and limits, then perform an explicitly labeled preparation/settling phase. No qpos/qvel writes after the measured episode starts. Record all preparation controls/assistance, residuals, contacts, activation and accepted engine state. Accepted reset requires finite state, equality error <1e-4, no unexplained penetration deeper than 2 mm and bilateral foot loading during its last 100 ms of preparation; thresholds must be development-validated before freeze. Failure to find such states blocks training; do not filter away hard final outcomes by re-running reset selection.

Generate reset specifications independently of candidate performance. Use model-aware integration for angle/quaternion perturbations. Initial candidate perturbations: root horizontal translation +/-1 cm, tilt/roll +/-2 degrees, named leg joint angles +/-0.5 degree, and generalized velocity noise +/-0.01 in the appropriate coordinate units. Reject invalid geometry deterministically during bank creation and retain every rejection. Pilot uses development resets only; after development, seal the complete final bank before formal policy training. Final reset settling cannot depend on which policy is being evaluated. Policy and baseline start from the identical integration state, including muscle activations; describe this as a local stability/recovery test, not learning to stand up.

### 4. Add feedback control with a bounded learning pilot

`groups.py`: convert the upstream full-body 138 index groups in `locomotionFull.json` to an immutable muscle-name partition. Assert exact 700-name coverage, no duplicates, actor isolation, finite actions and deterministic expansion. Hash names, ordering and transform. Use bounded normalized actions and reproduce upstream `sigmoid(5*(a-.5))`; a direct-excitation experiment is a separate action contract. This new whole-body action space cannot load v0.0.2's four-by-six arm logits as a stance checkpoint.

`stance_env.py`: implement Gymnasium `StanceEnv.reset/step`, `observe()`, `snapshot()` and `restore()`. Observation blocks are real measured joint state in root-aware coordinates, muscle activations, root-frame linear/angular velocity, gravity direction, feet/hand target errors, support telemetry and the previous held action. Freeze named slices/dimensions and normalizers; unit-test each against an independent engine calculation. Goals are a fixed stance and guard; no zeros standing in for missing observations. Only muscle controls drive the body after reset. Assert absence of root welds/assist actuators, gravity compensation, mocap coupling and unexpected applied forces; injected push is the sole allowed evaluation stimulus.

`stance_train.py`: use a locked maintained SAC implementation with a 138-action MLP; do not build a new PPO/league or silently invoke upstream's 64-env/50-million-step locomotion job. Add an optional `motor` dependency extra, lock exact resolved versions, and save the full learner configuration. Start with two hidden layers of 256, learning rate 3e-4, batch 256, gamma .99, tau .005, automatic entropy, one update per admitted transition and a 10,000-transition warmup. Replay capacity 100,000 transitions, reduced if measured storage would exceed 2 GiB; log actual observation/action bytes. These are pilot settings to freeze, not measured optimal values.

Motor reward is separate from boxing points: `exp(-4*tilt_rad**2) + exp(-20*horizontal_error_m**2) + .5*exp(-20*guard_error_m**2) - .01*mean(excitation**2) - .01*mean(delta_excitation**2)`, integrated using control dt. Terminate physical failure; the 20-second motor horizon is an external truncation with genuine final observation for SAC bootstrap. Invalid transitions go to fault storage, never the replay buffer as ordinary terminals. Evaluate deterministic actor means with frozen normalizers. Unit-test terminal/truncation/invalid handling and that controls are held for exactly ten 1 ms substeps.

First run a 100,000-control-transition development pilot (at most 1,000,000 physics substeps; 30-minute cap). Compare passive low excitation and the frozen initial feedback policy under the exact same model/reset protocol. Retain the initial policy as the formal paired baseline for each seed. Pilot reward improvement alone cannot pass the motor gate. If no useful stable behavior emerges, report the best development behavior and failure reasons; do not spend the formal budget until diagnosing resets, action coverage and support. Any imitation/assistance curriculum requires a separately documented follow-up protocol; it is not silently added here.

### 5. Freeze held-out stance and push tests

Use new training seeds **103, 211, 307**. Scenario namespaces: training 100000–199999; development 30000–30031; final quiet stance 40000–40063; final recovery 50000–50063. Derive all RNG keys from `(namespace, training_seed, scenario_id, purpose)` and persist them. Root probes/reset fitting use development only. No final ID is used for tuning, checkpoint selection, thresholds or variant selection.

Per seed evaluate the frozen initial and final actor on the same 64 quiet-stance and 64 push scenarios: **768 planned evaluation attempts**, each up to 20 seconds. Use the final scheduled checkpoint, not the best final-test score. Pair identical engine states and perturbations. Final starts are generated/validated before training and sealed by hash; final results are read only after protocol freeze. Failed final proof requires reporting that proof; a revised proof uses a new protocol and disjoint scenario IDs.

Quiet stance success: complete 20 seconds without motor failure, and over the final 2 seconds maintain torso tilt <20 degrees and pelvis horizontal drift <15 cm from reset. Recovery success adds the same bounds achieved within 2 seconds after the push ends and maintained for the rest of the episode. Compute tilt relative to calibrated anatomical upright, never a raw Euler component.

Recovery fixtures: at t=5 seconds apply one horizontal trunk-COM push over 50 ms, in directions 0/90/180/270 degrees and impulse 2 or 4 N s (eight repetitions of each direction/magnitude yields 64 scenarios). Integrate the actual applied world force to verify prescribed impulse within 1e-6 N s; no unlogged moment or solver-state write. Clear applied force on every later tick and before reset. Verify push scheduling is timestep independent with an independent free-body momentum fixture. Log both intended and delivered force/impulse. These are mild simulation disturbances, not calibrated opponent punches.

Absolute motor gate: each seed >=61/64 quiet successes (>=95%) and >=58/64 recovery successes (>=90%), zero invalids, all assistance/replay checks passing. Report physical failures in denominators. An unattempted proof is incomplete, not zero invalids. For learned improvement, report paired success differences and stable-seconds differences with paired scenario bootstrap 95% intervals (fixed bootstrap seed and 10,000 resamples), separately by training seed; a positive lower bound on quiet or recovery improvement for every seed supports that limited claim. Report all seeds; do not pool resets as independent training runs or imply three seeds establish broad algorithm superiority. A strong initial baseline can pass competence without establishing learning improvement.
