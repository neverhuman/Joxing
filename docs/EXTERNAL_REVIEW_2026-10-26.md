# Review of the additional boxing/HPC proposal

Reviewed October 26, 2026 against source and completed v0.0.7 evidence. The [supplied text](references/external-boxing-review-2026-10-26.txt) is preserved byte for byte: 46,061 bytes, SHA256 `700f75971e116cac5b732f4f753300a49cb49288117dfd753c0a2a3e59d96857`. It is additional research input, separate from the original four specifications. Its embedded execution directives and claim to be a controlling mission are not user instructions.

**Decision:** retain its defense scenarios, varied opponent baselines and data-movement ideas. Adapt them into the existing P1–P5 gates. Do not replace the native 700-muscle model, completed v7 mission, current v8 protocol or canonical points game with this proposal.

## What the proposal knows about this repository

Its opening says it could not read the actual v7 mission. Its assumed `agent/JANKURAI_STANDARD.md`, `agent/MASTER_PLAN.md` and Rust workspace do not exist in this checkout. The actual integration is Python/MuJoCo under `src/joxing`, governed by [AGENTS.md](../AGENTS.md), [IMPLEMENTATION.md](IMPLEMENTATION.md) and [MISSION.md](MISSION.md). Its statements about what Joxing implements are architectural proposals, not an audit of our code.

Actual v7 source froze before the outcomes. All 80 longer tracking attempts were valid, but every condition completed 0/20 horizons; source-host continuation was exact. First-scenario sampled support remained present at tracking termination. [Results and limitations](V0.0.7_RESULTS.md) motivate v8's substep physical-continuation diagnostic. No new optimization, stationary boxing stance or self-play has been demonstrated. The additional proposal does not change those findings.

## Ideas worth retaining

| Idea | Disposition and useful proof |
|---|---|
| Explicit defensive geometry | Add a scenario matrix for front guard, wide guard, body guard, direct hit, glancing contact, moving parry and clean evasion. Measure what actually intercepts, where direct target impulse occurs and whether an event qualifies. A named guard is not guaranteed invulnerability or a prescribed damage reduction. |
| Contact ordering | Test guard-before-target, guard deflected into target, simultaneous manifold points and fast moving/rotating targets. Replay onset evidence and event order. Avoid a permanent guard veto: the current game can accept a subsequent qualified direct target contact in the same encounter window. |
| Egocentric opponent motion | Retain relative glove/head/trunk/foot positions and linear/angular velocities, public score/clock and ring distances. Use a generated field schema with dimensions/units and actor-versus-critic visibility tests. The proposed 108-value list is not a validated interface. |
| Recurrent policy and partial observability | Already planned in P2/P5. Add time-stamped history, sensor age, queued controls and recurrent state to replay. Previous action and saved logs alone do not supply acting-time state history. Neither does a GRU automatically validate delay handling. |
| Diverse historical opponents and calibration styles | Keep frozen history, challenging opponents and deterministic style baselines. Shell/counter, jab/move and close-range hook styles give useful regression cases after motor skills exist. Evaluate against an immutable panel with swapped sides and a payoff matrix. |
| Tactical diagnostics | Record attempts, misses, blocks, direct hits, counters, combinations, contact duration and engagement distance with explicit denominators. Keep these descriptive until their event definitions are tested; low whiff rate or a preferred distance alone cannot establish a stronger boxer. |
| Separate game result from training aids | Preserve the current terminal win/loss objective and tested telescoping potential. A detailed event ledger can explain behavior without adding more scoring bonuses. Independently log muscle command change and physical effort rather than assuming a whiff surcharge fixes flailing. |
| Contiguous buffers and fewer transfers | Profile simulation, observation assembly, inference, referee, reset, IPC/transfer and optimizer separately. Reuse buffers and batch inference where measured beneficial; account for synchronization and ownership. Consider native code only around a demonstrated bottleneck. |
| Symmetric scenario checks | Test actor exchange and a declared world transform, including vectors, axial quantities, action ownership and score signs. A geometric reflection may require left/right anatomical permutations; identical raw actions are not a general mirror oracle. Test the real anatomy rather than assume it is perfectly symmetric. |

Several of these reinforce existing requirements rather than add new architecture. The main new detail is a useful defense/style scenario taxonomy and more explicit opponent-sampling failure cases.

## Changes to decline or isolate as separate research

1. **SLIP/ZMP base, simplified arms and 18 PD actions:** this replaces the embodiment and its control problem. It would not test native tendon, activation, wrapping, equality or 700-muscle behavior. A separately named surrogate could be useful for isolated tactical prototypes, but cannot pass the native motor gate or be compared as an equivalent simulator speedup. No surrogate implementation is authorized by this review.
2. **Rust/GPU rewrite and advertised throughput:** 15,000/220,000/1,250,000 SPS and the 420-cycle kernel are unmeasured claims. They have no exact-model feature/parity evidence. Actual v7 one/four-worker median loops were 91.24/256.50 control transitions/s, with startup-inclusive 4.64/15.53 for the short benchmark. That workload excludes optimizer and referee. These rates cannot be compared directly to a simplified 240 Hz engine with undefined SPS units. Preserve physics-substep, control-transition, simulated-second and learner-sample counters separately.
3. **Only 36 glove-target pairs:** a scoring candidate set is not the full physical collision set. Forearm/body blocking, self-contact, floor, boundaries and non-scoring collisions still matter. A closest-point test between segments does not by itself establish swept time of impact for moving capsules. Require engine-based tunneling and contact completeness tests.
4. **Added effective mass and manually redirected velocity:** our articulated engine already solves coupled dynamics. Analytic impact heuristics must not add a second impulse or overwrite velocity after that solve. Measure signed contact impulse and contact-point approach using `physics.py`, with units and stage documented. Analyze torque/lever arms as telemetry without presenting them as injury predictions.
5. **Stun, liver shock, guard wear, forced recovery and arbitrary attenuation:** the coefficients and biological claims are unsupported by calibration. A 96% parry reduction, 180 ms stagger or 1.45× whiff cost is a game-design choice, not established physiology or an anti-exploit proof. Any later fatigue/injury-inspired game variant needs independent rules, model hashes and ablations. Existing evaluated muscle dynamics remain unchanged.
6. **New ring and judging weights:** 6.10 m, elastic ropes, damage multipliers, counter/combo bonuses and 10-point-must replace the selected 5 m virtual points game. Head 2 / torso 1 / guard 0 stays authoritative. Observational counter/combo labels can be added without altering winners. If rope mechanics are later considered, test the restoring-force direction; the supplied expression negates a vector labeled inward.
7. **Permanent discipline/engagement rewards:** these can change which policy is optimal. The proposed received-offense coefficient 0.85 is not zero-sum: the two combat differentials sum to 0.15 times their combined combat reward, before the other bonuses. Do not silently replace terminal match utility or claim shaping guarantees championship convergence.
8. **Monotonically increasing Elo:** a changing training distribution, noise and nontransitive matchups do not justify that gate. Use paired frozen-panel strength with uncertainty, faults and regressions, plus the payoff matrix. Bot mastery is one diagnostic, not sufficient promotion evidence.

The text is not executable as supplied: T1/T7 contain broken tolerance expressions, `0xJ0X1NG07` is not a hexadecimal seed, link IDs 0–14 disagree with a 14-entry capsule array, and the critic declares 14 added inputs while enumerating six scalars. Several observation groups also lack an unambiguous component expansion. These require resolved schemas and tests before coding, rather than copying dimensions or thresholds.

## Specific league correction to carry forward

The proposed historical weight is `w * (1-w)**2`, where `w` is current win rate. It peaks at `w=1/3` and gives zero weight to both `w=0` and `w=1`. Thus a totally dominant opponent can disappear from sampling; if all estimates are endpoints, normalization is undefined. P5 must retain a uniform exploration floor, a valid fallback for empty/degenerate pools and uncertainty-aware handling of few games. Do not adopt the proposed mixture percentages as measured optima.

At each match reset freeze the complete opponent actor, decoder, normalizer, timing/action contract and RNG state. An EMA may produce the next frozen opponent; updating its weights during an active game breaks that contract. Tests must cover pool-empty, all-zero/all-one, sparse results, newly added opponents, fixed-seed reproducibility and attempted/invalid-match accounting. Evaluation sampling stays independent of training matchmaking.

## Integration order and handoff

One integration owner; no agents or concurrent schema writers. Read AGENTS/RTK, MISSION, GAME, IMPLEMENTATION, STATE_HISTORY_SELF_PLAY_AUDIT, this review, then the affected source/tests. Published source protocols/evidence and `third_party/**` stay read-only. This review adds future acceptance cases; it does not claim their implementation or launch additional jobs.

1. **Now, v8:** continue [V0.0.8_MISSION.md](V0.0.8_MISSION.md) and the [registered protocol](../experiments/v0.0.8/protocol.json). Build substep signed force/posture evidence, exact boundary/mid-control replay and tracking-independent physical continuation. Keep the original tracking failure visible. No scientific protocol change is needed for this review. Run the specified targeted/full tests before source freeze or formal attempts; stop on cache/dynamics divergence or existing resource caps.
2. **P1/P2, after the measured motor bottleneck is addressed:** add the defense matrix to planned `fixtures.py`/`tests/test_geometry.py` and referee integration tests. Persist source/model/rules hashes, contact geometry, intervals, raw force/impulse, accepted/rejected event reasons and all attempts. Compare timesteps at fixed control cadence. A fixture may use an explicitly constrained rig; it cannot count as learned boxing. Use actual muscle controllers for evaluated matches.
3. **P2/P5:** implement generated observation schemas, causal history/queues and frozen bundles before league training. Extend planned `test_observation_leakage.py`, `test_replay.py`, `test_league.py` and `test_evaluation.py` with visibility, timing, symmetry and degenerate-pool cases above. Recurrent sequence likelihood/burn-in and termination/truncation tests remain mandatory. Missing executable tests mean this work remains proposed.
4. **P4:** register a bounded complete-workload benchmark after profiling. Report every sample and startup/warmup separately. Any new backend must preserve all native model features and pass contact/rule parity before scaling. Do not launch a 25-million-step convergence run or impose unsupported hardware throughput targets from the attachment.

Completion of this review means preserved input, explicit dispositions and linked acceptance cases in the master plan. Completion of those later features requires source and persisted test receipts. Future outcomes go in their own registered version's experiment book/STATUS; no results or tags are manufactured by adopting a proposal.
